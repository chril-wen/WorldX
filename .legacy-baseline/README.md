# 改造前基准（只在阶段 5 用）

这个目录里是**阶段 5 改造前**的 `MapManager` / `PathfindingManager` 字面副本，
从 git 里按原样取出（`git show <commit>:client/src/systems/MapManager.ts`）。

## 干什么用

`packages/client-core/src/ab-comparison.test.ts` 同时加载**两套实现**，
喂同一份地图，比对输出**逐点相等**：

- 寻路：路径的每一个点都必须一样（差一格，角色就撞墙或绕远）
- 解析：网格、碰撞格、区域矩形、物件矩形都必须一样

## 为什么基准是「改造前的实现」而不是「新实现的快照」

新实现自己给自己当基准 = 自证清白，只能证明「实现没变」，
不能证明「没变的是对的那一份」。

阶段 4 的回归基准就是这么定的：**基准必须是改造前的字面实现**。

## 为什么原来不需要这个目录

改造前 `PathfindingManager` **一条测试都没有** —— 它是全仓唯一零测试的核心类。
而它的输出逐点决定角色怎么走。阶段 5 补上测试，第一件事就是先跟改造前对一遍。

## 什么时候删

阶段 5 验收通过、下一阶段不再需要 A/B 之后，整个目录删掉。
留着它的唯一价值是「能跟改造前比」，没有别的理由。
